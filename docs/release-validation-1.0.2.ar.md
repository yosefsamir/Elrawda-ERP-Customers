# تحقق محلي — 1.0.2

النسخة تطبق [تحسينات واتساب](whatsapp-tuning.ar.md) مع متصفح مخفي دائمًا.
هذه نتائج محلية على Linux، وليست اعتمادًا لتثبيت Windows أو إثبات منع التقييد.

| الفحص | النتيجة |
|---|---|
| `npm run typecheck` | نجح |
| `npm run test:core` | 84 ناجحًا، اختبار Windows واحد متخطى، دون فشل |
| `npm test` | 22 ناجحًا، دون فشل |
| `npm run build` | نجح، الخادم والواجهة |
| `CHROME_NO_SANDBOX=true npm run test:whatsapp:browser` | 5 ناجحة بمتصفح Chromium حقيقي |
| `npm run test:release` | نجح: تشغيل نسخة مبنية معزولة، HTTP/واجهة، نسخة احتياطية، استعادة، وإعادة تشغيل |
| `git diff --check` | نجح |

اختبار المتصفح الجديد يستعمل `Client.initialize()` من المكتبة المثبتة، ويتوقف
بعد إطلاق المتصفح وإعداد هويته وقبل أول انتقال إلى واتساب. تحقق من `about:blank`،
ومن التشغيل المخفي، وتطابق تعريف الصفحة مع المتصفح، وغياب معامل User-Agent مفروض.
لا توجد مصادقة لحساب أو إضافة أعضاء أو إرسال رسائل ضمن هذه الاختبارات.

اختبارات السياسة تتحقق من مشاركة الجدد والقدام للفاصل والحد، ومن احتساب النتائج
غير المؤكدة بعد إعادة إنشاء المحرك، وتوقف الدعوات للشركات القديمة افتراضيًا،
والإيقاف الدائم للمعالجة عند إشارة 429 أو 463. اختبارات الجلسة تتحقق من بقاء
منع الاسترداد بعد تغيير مالك الجلسة مع حفظ بيانات الاعتماد.

يلزم بناء Setup.exe والتحقق من الترقية على Windows قبل تثبيته عند العميل، وفق
[دليل النشر](windows-deployment.ar.md). لم يُنشأ أو يُنشر مثبت Windows في هذا التحقق.
تعطيل sandbox في أمر اختبار Linux يخص بيئة الاختبار فقط؛ إعدادات التشغيل العادية
تتركه مفعّلًا. لم تتم تجربة سلوك واتساب على رقم العميل.
