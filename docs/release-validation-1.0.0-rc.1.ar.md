# سجل تحقق 1.0.0-rc.1 — 31 أكتوبر 2026

الحزمة مرشحة للتثبيت والقبول على Windows. بيئة التنفيذ هنا Linux وNode.js 22.22.2، وليست Windows. لم تُستخدم بيانات التشغيل في الاختبارات ولم يتم ربط حساب واتساب أو إرسال رسائل فعلية.

## النتائج

- فحص TypeScript ناجح، وبناء السيرفر والعامل والواجهة ناجح.
- 38 اختبارًا للمنطق وحدود الشركات والأمان والمزامنة والطابور ومنع التكرار والإغلاق والترحيل والنسخ والاستعادة.
- 20 اختبارًا لمختبر واتساب؛ يستخدم العامل الإنتاجي الآن منطق فحص العضوية والإضافة الذي تغطيه هذه الاختبارات.
- تثبيت نظيف بـ`npm ci --omit=dev` في مجلد منفصل، وفحص عمل SQLite native وتحميل WhatsApp Client؛ لا توجد حزمة tsx فيه. نُزّل Chromium بشكل مستقل للاختبار.
- اختبار التشغيل من مجلد يحوي JavaScript المبني فقط، وباعتماديات production النظيفة: HTTP والواجهة والدخول، backup أثناء التشغيل، فحص النسخة، إغلاق منظم، restore، probe للمخطط، إعادة التشغيل، وبقاء الحساب والشركة. الاستعادة ترجع الشركات إلى Preview وموقوفة.
- عامل واتساب المبني أطلق Chromium مع Puppeteer المحدث ووصل إلى QR جديد، ثم أغلق الجلسة التجريبية دون ربط حساب. هذا يتحقق من بدء المتصفح ومساعدي العامل، ولا يثبت الإضافة أو الدعوة أو rollover على حساب مرتبط.
- فحص صياغة كل سكريبتات PowerShell باستخدام PowerShell 7 على Linux. نُفّذ أيضًا فحص البصمات ونسخ ملفات الإصدار وفق manifest بنجاح. هذا لا يثبت Task Scheduler أو SYSTEM أو PowerShell 5.1 على Windows؛ السكريبتات تستخدم صياغة متوافقة معه وتحتاج اختبارًا فعليًا.
- مراجعة المتصفح: مسودة الإعدادات ظلت موجودة بعد عدة دورات تحديث ثم حُفظت؛ «استئناف» احتفظ بـPreview؛ مصدر snapshot ظهر كنسخة محلية بتحديث يدوي؛ الفلاتر والتقارير فُحصت أثناء المراجعة.
- `npm audit --omit=dev`: صفر ثغرات معروفة وقت الفحص. التحديثات مثبتة في lockfile وتشمل Puppeteer 25.16.0 وglob 14.0.3 وminimatch 11.0.3 عبر overrides. يُعاد اختبار QR وعمليات واتساب عند أي تغيير لها.
- ZIP يضم قائمة ملفات مسموحة فقط، مع manifest وبصمات SHA256. لا يحوي data أو db أو node_modules أو ملفات TypeScript أو حسابات الاختبار.

## ما يجب اختباره على Windows قبل Live

تثبيت اعتماديات Windows وChromium من الشبكة، بدء Task Scheduler بحساب SYSTEM وإعادة الإقلاع، اتصال SQL الحقيقي بحساب قراءة فقط، وتجربة مصرح بها للإضافة والدعوة وrollover، ثم دورة تحديث وrollback فعلية بين إصدارين. الاختبارات المعزولة لا تغني عن هذه الخطوة. البيانات الحساسة وجلسة واتساب تظل على جهاز العميل؛ لا تُضمَّن في ZIP.
