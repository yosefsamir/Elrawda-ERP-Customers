# تثبيت WhatsApp-ERP على Windows وتحديثها

هذا الدليل لملف التثبيت `WhatsAppERP-Setup-<الإصدار>.exe`. الملف مكتفٍ بذاته: لا يحتاج الجهاز إلى Node.js أو npm أو Python أو Visual Studio، ولا إلى اتصال إنترنت أثناء التثبيت. يحتاج ربط واتساب ومزامنة SQL إلى الشبكة بعد التثبيت. نفّذ اختبار القبول على جهاز العميل قبل تفعيل Live.

## قبل الذهاب للعميل

- الجهاز: Windows 10 أو 11 أو Windows Server 2016 أو أحدث، إصدار 64-بت، بحساب له صلاحية مسؤول.
- المساحة: 3 جيجابايت فارغة على الأقل على قرص النظام أثناء التثبيت.
- المنفذ `3211` يجب أن يكون متاحًا. إذا كان مستخدمًا سيتوقف التثبيت برسالة واضحة دون تغيير البيانات.
- افحص بصمة الملف قبل التشغيل: `Get-FileHash .\WhatsAppERP-Setup-<الإصدار>.exe` وقارنها بملف `.sha256`.
- الملف غير موقّع رقميًا حاليًا، لذلك قد يعرض Windows تحذير SmartScreen. لا تتجاوز التحذير إلا بعد مطابقة البصمة.

## أول تثبيت

1. شغّل ملف التثبيت ووافق على طلب صلاحية المسؤول.
2. اتبع المعالج حتى النهاية. يتحقق المثبت من الملفات ويشغّل Chromium بهوية الخدمة قبل التفعيل.
3. إذا فشل أي فحص، يتوقف المعالج برسالة خطأ ولا يسجل البرنامج كمثبت. أعد التشغيل بعد علاج السبب.

التثبيت الصامت لأدوات الإدارة عن بعد:

```powershell
.\WhatsAppERP-Setup-<الإصدار>.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART
```

رمز الخروج `0` يعني نجاح التثبيت، وأي رمز آخر يعني الفشل.

يعمل التطبيق كمهمة مجدولة باسم `WhatsAppERPOperations` بحساب `LOCAL SERVICE` محدود الصلاحيات، ويعمل Chromium داخل sandbox. لن تجده في Services.msc. يبدأ تلقائيًا مع Windows دون تسجيل دخول.

افتح **http://127.0.0.1:3211** على نفس الجهاز. أنشئ مسؤولًا بكلمة مرور تخص العميل ثم أنشئ الشركة. لا يوجد حساب افتراضي ولا كلمة مرور عامة. أدخل اتصال SQL بحساب مخصص للقراءة فقط، ونفّذ أول مزامنة، واربط واتساب بمسح رمز QR.

الواجهة محلية فقط؛ لا تفتح تلقائيًا من جهاز آخر على الشبكة. لو المطلوب تشغيلها من أجهزة الفروع، يحتاج ذلك إعداد وصول مختلف ولا يكفي تغيير عنوان المتصفح.

## البيانات التي يجب الحفاظ عليها

- `C:\ProgramData\WhatsApp-ERP\data\app.sqlite`: حسابات التطبيق والشركات والعملاء والإعدادات والنتائج وسجل منع التكرار.
- `secret.key`: مفتاح فك بيانات SQL؛ يجب أن يرافق نسخة قاعدة التطبيق.
- `whatsapp-auth`: جلسة واتساب. لا تُنسخ إلى بيئة اختبار تتصل بالحساب الحي بالتوازي.
- `C:\ProgramData\WhatsApp-ERP\service.json`: مسار الإصدار الحالي وNode ومجلد البيانات والمنفذ؛ لا توجد كلمات مرور SQL داخله.
- `logs`: سجلات التشغيل، ويمكن لأي مستخدم على الجهاز قراءتها من اختصار «Installation Logs». باقي مجلد الحالة مقيّد إلى SYSTEM وAdministrators وهوية الخدمة.

قاعدة ERP الأصلية مستقلة ولا تدخل ضمن حزمة التحديث. استعلامات التطبيق عليها للقراءة؛ افْرض ذلك بصلاحيات حساب SQL نفسه. مصدر snapshot المحلي للتطوير فقط ولا يستقبل الجديد تلقائيًا؛ ملفات snapshot لا تُشحن مع حزمة العميل.

## النسخ الاحتياطي

المثبت يسجل مهمة يومية الساعة **03:00 بتوقيت جهاز Windows** لنسخ SQLite ومفتاحها. إذا كان الجهاز مغلقًا في ذلك الوقت، تعمل المهمة بعد التشغيل التالي. تُحفظ آخر 14 نسخة يومية باسم `daily-*`، وتُسجل النتيجة في `logs\backup.log`. النسخة اليومية لا تشمل جلسة واتساب.

نسخة يدوية أثناء التشغيل:

```powershell
.\scripts\windows\backup.ps1
```

نسخة كاملة تشمل جلسة واتساب، مع توقف قصير منظم:

```powershell
.\scripts\windows\backup.ps1 -Offline
```

إذا خصّصت مجلد الحالة، مرّر `-StateRoot` نفسه إلى أدوات الإدارة. مجلد النسخ هو `C:\ProgramData\WhatsApp-ERP\backups`. انسخ دوريًا نسخة محمية إلى وسيط/جهاز آخر؛ النسخ الموجودة على نفس القرص لا تغطي فقد القرص. لا يوجد حذف تلقائي للنسخ القديمة في هذا الإصدار؛ راقب المساحة وطبّق سياسة الاحتفاظ المناسبة للعميل.

فحص نسخة دون استعادتها، من مجلد الإصدار المثبّت:

```powershell
$env:EMOJI_DATA_DIR='C:\ProgramData\WhatsApp-ERP\data'
node .\dist\runtime\scripts\maintenance\admin.js verify-backup --input 'C:\ProgramData\WhatsApp-ERP\backups\اسم-النسخة'
```

## تحديث إلى إصدار جديد

شغّل ملف التثبيت الأحدث على نفس الجهاز. يتحقق الملف من الإصدار الجديد قبل إيقاف القديم، ثم يأخذ backup كاملًا تحت `backups\before-*`، ويجرب ترحيل المخطط على نسخة معزولة، ثم يبدّل الإصدار ويختبر استجابة الخادم. إذا لم يعمل الإصدار الجديد، يرجع تلقائيًا إلى السابق متى كان المخطط متوافقًا. لا يُستبدل مجلد بيانات العميل.

تشغيل نفس الإصدار مرة أخرى يصلح التثبيت الحالي دون حذف البيانات.

توجد فترة توقف قصيرة لتطبيق الروضة وإعادة اتصال واتساب؛ ERP نفسه يستمر في العمل وتُلتقط السجلات الجديدة بعد عودة المزامنة. لا يوجد ضمان لصفر توقف. لا تشغّل نسختين على نفس البيانات أو نفس جلسة واتساب؛ يوجد قفل يمنع تكرار خادم البيانات.

إذا فشل الإغلاق لا تُجبر العملية على التوقف لمجرد إكمال التحديث؛ راجع السجلات. إذا ظهرت `data\maintenance.flag` تظل محاولة إعادة التشغيل معطلة حتى إكمال/حل إجراء الصيانة. لا تحذف القفل أو العلامة أثناء عملية أخرى جارية.

## الانتقال لطوابير الفواتير في 1.1

التحديث يبقي الشركات على المحرك الحالي وإعداداته حتى التحويل الصريح. اتبع [دليل انتقال الطوابير](invoice-workers-upgrade.ar.md): راجع الربط والجروبات واضبط حدود الفروع، ثم شغّل الخدمة المطلوبة من صفحتها في الإعدادات. لكل خدمة مفتاح مستقل، والرسائل متوقفة افتراضيًا. يفحص التشغيل اتصالي ERP وواتساب ويجهز الفواتير قبل التفعيل؛ الإيقاف متاح دون اتصال. بعد تفعيل الطوابير أو الرسائل يمنع الرجوع إلى إصدار لا يفهمها؛ لا تستعد قاعدة قديمة تلقائيًا.

## إلغاء التثبيت

من «التطبيقات المثبتة» في Windows اختر WhatsApp-ERP ثم إلغاء التثبيت. يوقف ذلك الخدمة ويحذف المهام المجدولة والبرنامج، ويحتفظ بكل بيانات العميل تحت `C:\ProgramData\WhatsApp-ERP`. إعادة التثبيت لاحقًا تستخدم نفس البيانات. إذا كان ملف مفتوحًا في برنامج آخر، يتوقف الإلغاء برسالة خطأ؛ أغلق البرنامج وأعد المحاولة.

## الرجوع والاستعادة

الرجوع لكود الإصدار السابق مع الاحتفاظ **بالبيانات الحالية**:

```powershell
.\scripts\windows\rollback.ps1
```

يرفض الأداة الرجوع إذا كان الإصدار السابق لا يقرأ المخطط الحالي. لا تُرجع قاعدة قديمة تلقائيًا بعد تنفيذ رسائل جديدة: هذا يفقد التاريخ اللاحق وقد يؤدي لتكرار عمليات خارجية.

عند الحاجة الفعلية لاستعادة backup، بعد تقييم البيانات والعمليات التي حدثت بعده:

```powershell
.\scripts\windows\restore.ps1 -BackupPath 'C:\ProgramData\WhatsApp-ERP\backups\اسم-النسخة'
```

الاستعادة تحفظ مجموعة الملفات الحالية في مجلد أمان، وتتحقق من القاعدة والمفتاح، وتعيد **كل الشركات إلى Preview وموقوفة**. سوِّ العمليات التي حدثت بعد النسخة قبل تفعيل Live. النسخة التي أخذت أثناء التشغيل لا تحتوي جلسة واتساب؛ تحتفظ الاستعادة بالجلسة الحالية حينئذ. إذا انقطع الجهاز أثناء الاستعادة تمنع علامة `restore-in-progress.json` تشغيل الخادم؛ تحتوي مساري النسخة ومجلد الأمان لتسهيل الاستعادة اليدوية لمجموعة القاعدة والمفتاح المطابقة.

فحص تشخيصي بعد التثبيت أو إعادة الإقلاع:

```powershell
.\scripts\windows\diagnose.ps1
```

## اختبار القبول قبل Live

1. نجاح الدخول، حفظ الإعدادات وبقاؤها بعد أكثر من أربع ثوانٍ، والفلاتر والتقرير والتصدير.
2. مزامنة SQL بحساب قراءة فقط؛ التحقق من عميل جديد ومن تصحيح رقم قديم باستخدام «مراجعة كل تعديلات العملاء». المراجعة الكاملة تلقائية كل ساعة (60 دقيقة) بجانب دورة الجديد كل 30 ثانية.
3. ربط واتساب بالحساب المطلوب والتحقق من صلاحيات الأدمن والجروبات. تجربة محدودة على رقم مصرح به للإضافة/الدعوة ووجهة اختبار.
4. تجربة إعادة التشغيل وإعادة الاتصال، ثم backup وrestore على بيانات تجريبية، وتحديث وrollback بين إصدارين مختبرين قبل الاعتماد على المسار عند العميل.
5. التحقق من Task Scheduler بعد إعادة إقلاع Windows، ومن ملفات `logs`، ومن إعادة اتصال واتساب دون رمز QR جديد بعد إعادة الإقلاع.

النتائج المجهولة لا تُعاد تلقائيًا. حفظ الفروع أو الإعدادات لا يعيد إرسالها. استخدم «فحص الحالة» لتسوية عضوية عملية سابقة بقراءة الجروب دون إضافة أو إرسال؛ الدعوة مجهولة الإرسال تحتاج مراجعة بشرية. حصة القديم تحسب محاولة الرقم/الوجهة مرة واحدة قبل تنفيذها، بما يشمل النتيجة المجهولة؛ دعوة الخصوصية التابعة لها لا تستهلك حصة ثانية. العميل الجديد لا يستهلك حصة القديم.
