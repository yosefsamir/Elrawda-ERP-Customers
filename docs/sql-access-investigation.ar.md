# فحص وسيلة اتصال ERP

فحص ساكن لملفات نسخة البرنامج بتاريخ 30 أكتوبر 2026، دون تشغيل executables أو تعديل الملفات الأصلية.

- اختبار الجهاز الرئيسي وصل إلى SQLMOHSEN لكن Windows Authentication رُفض لأن حساب Windows معطل في SQL. لم تُختبر قراءة العملاء.
- alrawda.exe وalrawdamin.exe يحتويان قيمة افتراضية في MySettings.AlrawdaConnectionString، مع Password فارغ في النص. هذا لا يثبت أن باسورد السيرفر فارغ. أجسام الدوال في النسخة مموهة/غير قابلة للقراءة المباشرة بالأداة المستخدمة.
- البرنامج المساعد seaprate/autosendtoserver/autosendtoserver.exe قابل للفحص. Form1_Load يحدد SQLMOHSEN وحساب sa وباسورد افتراضي مكتوبًا في الكود؛ لم يُنسخ السر إلى هذا التقرير أو سكربت الفحص.
- إن وجد ملف instant في مجلد العمل الحالي، يقرأ: السطر الأول instance، الثاني password، الثالث user، الرابع database override. الملف غير موجود في نسخة الفولدر المفحوصة. هذا مسار مثبت في البرنامج المساعد، ولم نثبت أنه نفسه في البرنامج الرئيسي.
- اسم القاعدة المحلية قد يُشتق من مسار ملف al*.mdf بعد إزالة حرف القرص والفواصل والنقط والمسافات والامتداد، بدل اسم alrawda المجرد. لذلك الاختبار التالي يتصل بـmaster ويعرض أسماء القواعد وحالتها، ولا يفترض اسم قاعدة ERP.
- السكربت scripts/diagnostics/test-sql-access.ps1 يستخدم حساب sa لاختبار مؤقت فقط، ويطلب السر بصورة مخفية. لا يغيّر إعدادات أو بيانات أو صلاحيات. نجاحه لا يعني اعتماد sa كحساب خدمة للإنتاج.

الخطوة المطلوبة من الجهاز الرئيسي: تجربة واحدة بالباسورد الافتراضي المستخرج. إن رُفض، نفحص ملف instant من مجلد التشغيل الفعلي بدل التخمين أو تكرار كلمات مرور. بعد نجاح الاتصال نحدد قاعدة ERP ونختبر قراءة جدول العملاء.

## تحديث اختبار السيرفر الحقيقي

أكد المستخدم نجاح Test Connection عبر ملف UDL على localhost\SQLMOHSEN باستخدام بيانات SQL الافتراضية المستخرجة، وأفاد بظهور قواعد البيانات. هذا يثبت صلاحية الاتصال وقت الاختبار؛ لم تُحسم بعد هوية قاعدة ERP الفعلية ولا صلاحية قراءة جدول العملاء. محاولة PowerShell السابقة أظهرت مستخدمًا فارغًا، فلا تُعامل كاختبار صلاحية للباسورد. الخطوة التالية تحديد القاعدة وفحص SELECT محدود دون تعديل.
