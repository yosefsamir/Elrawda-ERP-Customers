# الروضة — إدارة العملاء وواتساب

تطبيق محلي بـReact وFastify وSQLite، يقرأ عملاء ERP من SQL Server بحساب قراءة فقط، ويعزل بيانات كل شركة. النسخة المرشحة الحالية `1.0.0-rc.1`.

## تجهيز جهاز العميل Windows

استخدم حزمة ZIP التي ينشئها `npm run release`، ثم اتبع [دليل التثبيت والتحديث والاستعادة](docs/windows-deployment.ar.md). الحزمة تحتوي واجهة وسيرفر وعامل واتساب مبنيين، ولا تتضمن بيانات التطوير أو جلسات واتساب أو `node_modules` الخاصة بـLinux. تحتاج Node.js 22.22 أو أحدث ضمن 22.x على Windows x64 وإنترنت عند تثبيت اعتماديات التشغيل وChromium.

البيانات مستقلة عن الإصدارات تحت `C:\ProgramData\Elrawda\data`. لا تستبدلها أثناء تحديث الكود. التحديث يشمل إغلاقًا منظمًا وbackup وتجربة الترحيل، مع توقف قصير لتطبيقنا. ملف `secret.key` جزء لازم من نسخة قاعدة التطبيق؛ جلسة واتساب تُنسخ فقط بعد إغلاق المتصفح. يوجد backup يومي لقاعدة التطبيق والمفتاح، وأدوات backup كامل وrestore وrollback للكود.

## التطوير والتحقق

```sh
npm ci
npm run typecheck
npm run test:core
npm test
npm run build
npm run test:release
npm start
```

`npm run build` يبني السيرفر والعامل تحت `dist/runtime` والواجهة تحت `dist/web`. `npm start` يشغّل JavaScript المبني دون tsx. `npm run dev` و`npm run dev:web` للتطوير فقط. `npm run release` يبني ZIP ببصمات SHA256 من قائمة ملفات مسموحة؛ مجلدات `data` و`db` والاختبارات وملفات التطوير لا تدخل الحزمة.

افتح http://127.0.0.1:3211 على جهاز التشغيل. أنشئ حساب المسؤول ثم الشركة؛ لا يوجد حساب افتراضي. عدّل مسار البيانات باستخدام `EMOJI_DATA_DIR` والمنفذ باستخدام `PORT` وجذر ملفات الإصدار باستخدام `EMOJI_APP_ROOT` عند الحاجة. الواجهة محلية فقط، ولا يفتح المثبت وصولًا شبكيًا.

## السلوك الحالي

- Preview للقراءة والتصنيف؛ تفعيل Live إجراء مستقل عن الاستئناف.
- أولوية للعملاء الجدد المؤهلين؛ دفعات القديم ضمن ساعات القاهرة والحصة اليومية، سواء بجروب عام أو لكل فرع.
- الحصة اليومية للقديم تحجز محاولة الرقم/الوجهة مرة قبل الكتابة الخارجية، بما يشمل النتائج المجهولة؛ دعوة الخصوصية التابعة لا تخصم مرتين.
- سجل دائم لمنع تكرار الإضافة والدعوة والـrollover للشركة والهاتف والوجهة. النتيجة المجهولة تُراجع ولا يعيدها حفظ الإعدادات أو إعادة التشغيل. «فحص الحالة» يقرأ العضوية السابقة دون إرسال.
- قبول الإضافة لا يُعرض كتأكيد عضوية إلا بعد رصدها. إرسال الدعوة يتطلب نتيجة إرسال ومعرف رسالة.
- مزامنة الجديد كل 30 ثانية ومراجعة كاملة للتعديلات كل 15 دقيقة؛ يمكن طلب المراجعة الكاملة يدويًا. التواريخ اليومية تعني أول اكتشاف محلي، ولا تدّعي تاريخ تسجيل غير متاح في ERP.
- فلاتر وبحث وتقارير وتصدير CSV، مع عزل الشركات وحماية صيغ الجداول وتشفير إعدادات SQL محليًا.
- عامل واتساب منفصل وجلسة نشطة واحدة في العملية. استعادة الاتصال تلقائية للجلسة المحفوظة؛ لا تُشغَّل شركات متعددة في الوقت نفسه على عامل واحد.

## حدود التحقق

يلزم اختبار قبول على Windows بحساب تشغيل SYSTEM وعلى اتصال العميل الحقيقي وواتساب المصرح به قبل Live. اختبارات mocks وبناء Linux وفحص صياغة PowerShell لا تثبت هذه التكاملات. لا يدعم هذا الإصدار نقل تاريخ المحادثات القديم أو وضع شعار الشركة تلقائيًا على الجروبات الجديدة. نتائج الإرسال المجهولة لا تُعاد تلقائيًا لتجنب التكرار.

تفاصيل مراجعة ما قبل الإصلاح في [تقرير المراجعة](docs/production-review-2026-10-31.ar.md)، وحالة التسليم في [حالة التنفيذ](docs/implementation-status.ar.md).
